\chapter{ASSUMPTIONS, CONSTRAINTS \& DEPENDENCIES}

\section{Assumptions}
The following assumptions were made to define the project scope and planning:
\begin{itemize}
    \item \textbf{Mock Infrastructure:} It is assumed that the simulated Payment Gateway API is fully documented and available for integration from the start of Sprint 3.
    \item \textbf{Hardware Readiness:} Customers and event staff are assumed to possess smartphones capable of rendering modern web browsers and running the mobile scanning module.
    \item \textbf{Environmental Stability:} Stable internet connectivity is assumed to be provided by the venue for the online aspects of ticket validation.
    \item \textbf{Data Volume:} Planning is based on a maximum capacity of 50,000 tickets per event and a peak of 5,000 daily transactions.
\end{itemize}

\section{Constraints}
Constraints that may impact the triple project management boundary (Scope, Time, Cost):
\begin{itemize}
    \item \textbf{Time Constraint:} The project must be completed within a strict \textbf{5-month} window to meet Dề Dê's event season.
    \item \textbf{Financial Constraint:} Total project expenditure is capped at \textbf{1.5 Billion VNĐ}. Any scope creep must be strictly managed via the Scrum Change Management process.
    \item \textbf{Human Resources:} The team is limited to \textbf{5 members}, requiring high cross-functionality and efficiency.
    \item \textbf{Technical Requirement:} The mobile app must maintain offline functionality for short durations, adding complexity to local data synchronization.
\end{itemize}

\section{Dependencies}
\begin{itemize}
    \item \textbf{Stakeholder Availability:} Timely feedback from "Dề Dê Startup" stakeholders during Sprint Reviews is critical to avoid development delays.
    \item \textbf{Regulatory Compliance:} The project depends on the current local regulations regarding e-commerce and digital ticketing being stable throughout the development cycle.
\end{itemize}
