\chapter{PROJECT GOALS}

\section{Business Need and Problem Justification}
The project is initiated to address the critical operational challenges faced by "Dề Dê Startup" during its rapid expansion (averaging 15–20 events annually). The current manual ticketing process via social media and bank transfers has led to several business-critical issues:
\begin{itemize}
    \item \textbf{Revenue Loss:} The emergence of counterfeit tickets and the inability to track unique seats have caused direct financial leakage.
    \item \textbf{System Instability:} Existing manual workflows cannot handle peak traffic during "golden hour" sales, leading to system crashes and lost sales opportunities.
    \item \textbf{Operational Inefficiency:} Slow manual check-in processes at gates cause congestion and poor attendee experiences.
    \item \textbf{Lack of Data Insights:} The absence of an automated system prevents the collection and analysis of customer behavior data, hindering strategic marketing efforts.
\end{itemize}

\section{Project Objectives}
The primary goal is to deploy a high-concurrency digital platform to automate the entire ticketing lifecycle, aiming for:
\begin{itemize}
    \item \textbf{Scalability:} Support 10,000 concurrent users (simulated) with a response time of $<$ 2 seconds.
    \item \textbf{Efficiency:} Reduce gate check-in time to $<$ 5 seconds per person.
    \item \textbf{Financial Growth:} Increase overall ticket revenue by 20\% through optimized sales channels and fraud prevention.
\end{itemize}

% --- CHAPTER 2: DELIVERABLES ---
\chapter{DELIVERABLES}

The project will provide the following measurable deliverables:

\section{Centralized Web Application}
\begin{itemize}
    \item \textbf{Create} an end-to-end ticketing portal for customers featuring dynamic seating charts.
    \item \textbf{Provide} an Administrative Dashboard for event organizers to manage multiple concurrent events and inventory.
    \item \textbf{Integrate} a payment retry mechanism and basic anti-fraud solutions to ensure transaction integrity.
\end{itemize}

\section{Mobile Scanning Module}
\begin{itemize}
    \item \textbf{Deliver} a mobile application for staff to validate tickets via QR code.
    \item \textbf{Provide} short-term offline functionality to ensure uninterrupted check-in during network instability.
\end{itemize}

\section{Reporting \& Infrastructure}
\begin{itemize}
    \item \textbf{Establish} an automated QR code generation engine that ensures zero duplication across 50,000 tickets per event.
    \item \textbf{Research and Implement} a load-balanced infrastructure capable of handling 5,000 transactions per day.
    \item \textbf{Deliver} comprehensive sales and behavioral analytics reports.
\end{itemize}

% --- CHAPTER 3: SCOPE DEFINITION ---
\chapter{SCOPE DEFINITION}

\section{In Scope}
The project will include the following activities and functional areas:
\begin{itemize}
    \item Development of the Core Ticketing Engine (Event creation, inventory, and dynamic seating).
    \item Implementation of a Simulated Payment Gateway API (mocking successful/failed transactions).
    \item Development of the QR validation system (Web-based generation and Mobile-based scanning).
    \item Deployment of the system using an Incremental/Iterative approach under the Scrum framework.
    \item Performance testing for 10,000 concurrent users and 98\% transaction success rate.
\end{itemize}

\section{Out of Scope}
The project will not include:
\begin{itemize}
    \item \textbf{Live Payment Integration:} Integration with actual production banks or e-wallets (Momo, VNPay, etc.) is excluded; only simulated APIs are used.
    \item \textbf{Customer-facing Mobile App:} The scope is limited to a Web Application for users and a Mobile App for staff/check-in only.
    \item \textbf{Hardware Procurement:} Supply of smartphones or professional QR scanners for event staff.
    \item \textbf{Content Marketing:} Creation of marketing materials or managing social media advertisements for Dề Dê Startup.
\end{itemize}
